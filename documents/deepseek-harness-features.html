① 输入与附件 Input & Attachments

💬 多行文本输入框
底部固定输入框,自动伸缩高度(上限 ~6 行)。Enter 发送、Shift+Enter 换行。空行不影响发送。
UI: composerEnter / Shift+Enter
📎 文件 / 图片附件
支持拖拽与点击上传,常见格式: PDF / DOCX / XLSX / TXT / MD / 代码文件 / 图片。图片走多模态 VLM,文档走 OCR + 抽取文字作为上下文。
单文件 ~50MB文档解析质量参差
🎙️ 语音输入
麦克风按钮 → 浏览器 Web Speech API(或自研 ASR)转写为文本注入输入框,不直接发送。需要授权麦克风。
Web Speech需授权
📋 粘贴自动检测
粘贴大段文本时提示"检测到 N 字,已附加为上下文";粘贴图片自动上传为附件。
剪贴板监听
�️ 中断生成
流式期间输入框旁 Stop 按钮,中断当前生成。已生成的 token 保留,后续可继续。
SSE cancel
↩️ 重生成 / 编辑重发
AI 回复下方:复制、点赞、点踩、重新生成;用户消息:编辑后重发(分支成新会话线)。
分支会话反馈回流训练

② 模型与深度思考 Model & Reasoning

🧠 深度思考(R1)Toggle
顶部模型选择器旁"深度思考"开关。开启走 DeepSeek-R1(高推理),关闭走 V3(快对话)。两套系统提示词与采样参数。
推理模式R1 慢 + 长 CoT
🔀 模型切换
下拉选择 V3 / V3.1 / V3.2-Exp / R1,会话级生效。不同模型计费单价不同。
会话级跨模型上下文不互通上下文窗口不同
📜 思维链展示
R1 模式下默认折叠"思考过程",可点开查看完整 CoT;展开后与最终答复分两栏/两块渲染。
折叠 / 展开可复制
🌊 流式输出
SSE 流式 token,首字延迟 1-3s。Markdown 实时解析、代码块带语法高亮。流式期间不阻塞输入框,但可中断。
SSEMarkdown 实时
🎛️ 高级参数
设置 → 模型参数: Temperature / Top-P / Max Tokens / System Prompt(F12 改 system prompt 注入)。
TemperatureTop-PMax Tokens
R1 与 V3 在 harness 层的关键差异
  • Prompt 模板不同: R1 用 chat template 加 reasoning system prompt,V3 用普通 instruct template。
  • 解析策略: R1 解析 <think>...</think> 区段折叠,V3 直接当正文。
  • 采样参数: R1 倾向 temperature=0.6,top_p=0.95;V3 默认 1.0 / 1.0。
  • 工具调用: 早期 R1 无 function calling,网页版以提示词工程包装;V3 / V3.2 原生支持。
  • 上下文窗口: V3 系列 64K-128K,R1 网页版 32K 上下文(CoT 占用大)。

③ 联网与工具 Web & Tools

🌐 联网搜索
输入框旁"联网"开关。开启后模型自动调用内置搜索引擎,回复带引用角标 [1] [2] + 底部来源列表(标题 / URL / 摘要)。
原生工具引用 [n]仅中文站优
� 文件读取 / 解析
上传附件被自动解析(图片走 VLM、文档走 OCR + 抽取),解析结果注入 prompt 上下文。解析失败的图片 / 扫描件会有提示。
PDF/DOCX/XLSX图片 OCR
🧮 代码执行(受限)
部分版本提供 Python 沙箱执行(类似 ChatGPT Code Interpreter),可生成图表 / 跑数据。沙箱无网络、有限内存与时长。
沙箱无网Python
🔌 API 工具(开发者)
API 平台支持 function calling;网页版未暴露完整 function call UI,仅通过 system prompt 间接用。
function_call网页端受限

④ 内容渲染 Content Rendering

📝 Markdown 实时解析
流式期间按块增量渲染(避免每 token 全量重 parse)。支持标题、列表、引用、表格、分隔线、行内 code、链接。
块级增量表格 / 列表
💻 代码块 + 高亮
围栏代码块带语法高亮(类 prism / shiki),右上角"复制"按钮与"运行"(若启用代码执行)。语言标签。
语法高亮一键复制
🧮 LaTeX 公式
行内 $...$ 与块级 $$...$$ 走 KaTeX 渲染。失败时降级为纯文本。
KaTeX降级路径
🖼️ 图片 / 图表预览
模型生成图片(如 R1 思维链配图、或代码执行输出的图表)内联预览,带"查看大图"。
内联查看大图
📚 引用角标 + 来源列表
联网模式下角标 [n] 跳到文末来源,带标题 / 域名 / 时间。来源可点开新窗口。
角标跳转来源元数据
🎨 主题切换
浅色 / 深色 / 跟随系统。背景可设纯色 / 渐变。

关键观察: DeepSeek Chat 网页版是一个典型的"对话优先 + 内置工具"形态,没有插件生态,工具调用能力主要服务于"联网 + 代码执行"两个内置场景,不像 Claude Code / Cursor 那样深度集成 Agent 工具链。

与 KinetAios 对比 DeepSeek vs KinetAios

🟦 DeepSeek Chat

  • 对话优先,工具能力薄弱(仅联网 + 代码沙箱)
  • 模型选择 + 深度思考 toggle 是核心差异点
  • 用户上下文管理简陋(无显式 persona / ctx mode)
  • 无插件生态、无 MCP
  • 记忆为云端跨会话,用户不可控
  • 本地优先的桌面端能力 = 无

🟧 KinetAios

  • 多引擎(Direct / DirectV2 / V3 / Claude Code / Codex / 插件)
  • 工具链丰富: shell / read_file / write_file / web_fetch / recall_memory / MCP
  • 会话级 persona toggle + ctx mode(low / mid / high fidelity)
  • 插件 SDK v3:声明式 manifest 可贡献新引擎
  • 长期记忆五层(SQLite + Embedding + FTS5),完全本地
  • 桌面端(Electron),本地优先,数据不出端
对标差距: DeepSeek 的"深度思考 toggle + 流式 CoT 折叠"是非常直观的 UX 设计,KinetAios 在 DirectV2 / V3 模式下也可加类似可视化,但目前只在 settings 里开关 plan 模式,UI 表达弱。
