五层记忆架构

KinetAios 的记忆系统不是单一的"对话历史"，而是五层独立但协同的记忆子系统。每层有不同的生命周期、存储格式和注入策略，共同构成一个完整的认知记忆栈。

L0 Memory Blocks · 结构化核心记忆

借鉴 Letta Memory Blocks 设计。每轮对话始终注入，是 AI 的"常驻意识"。Agent 可通过 memory_replace / memory_append 工具主动编辑。

🧬 persona read-only

替身画像（用户做事风格）。由 generatePersona() 从历史对话+记忆 LLM 生成，2000 字符上限。

👤 user_profile

用户画像：身份、偏好、习惯、技术栈。3000 字符上限，Agent 可原地编辑。

📁 project_context

项目上下文：当前项目的技术栈、目录结构、命名规范。3000 字符上限。

🎯 active_goals

当前目标：正在进行的任务、待办事项。1500 字符上限，随任务进展更新。

表: memory_blocks 注入: system → user msg (_memory: true) XML 格式: <memory_blocks>...
L1 Semantic Facts · 语义记忆库

原子级事实陈述（"用户偏好 Tailwind"），由 extractMemories() 在每轮 done 后异步提取。支持 embedding 向量索引 + FTS5 全文检索双重召回，带重要性评分和时间衰减。

📝 facts (memories 表)

id · content ≤18字 · importance 1-10 · conversation_id · created_at

🔢 embeddings

Float32Array 向量。GLM embedding-3 模型，768 维。存储为 BLOB，cosine 相似度暴力 O(n) 计算。

📊 memory_meta

weight 衰减权重 · last_used 最后命中时间 · use_count 命中次数

🔗 memory_triples

知识图谱三元组 (S→P→O)。如 用户 → 偏好 → TypeScript。每次提取同步生成。

表: memories, memory_embeddings, memory_meta, memory_triples 注入: 按需检索 top-N 注入 systemPrompt 触发: done 事件后异步提取
L2 Episodic Memory · 会话叙事摘要

每次会话 done 后自动提取的叙事摘要（"这次会话做了什么"），与 L1 的原子事实互补。用于跨会话回忆"上次那个 bug 怎么修的"。

📋 episodic_memories

summary 3-5 句话 ≤200字 · importance 1-10 · tags 关键词标签 · conv_id

🔑 摘要重点

  • 任务目标 + 根因/解决方案
  • 改了哪些文件/模块
  • 关键决策 + 用户学到什么
表: episodic_memories 注入: 最近 5 条注入 systemPrompt 尾部
L3 Conversation History · 对话全文索引

所有历史对话的 role + content 被写入 FTS5 虚拟表。recall_memory 工具在此做全文检索，让 Agent 能回忆起任何历史对话片段。

🔍 history (FTS5)

role (user/assistant/shell) · content 全文。MATCH 查询，rowid DESC 排序。

💬 turns + conversations

完整会话结构：turns.data 存 JSON (prompt/answer/steps/cost)。conversations 存引擎/模型/cwd/分支/目标等元数据。

表: history (FTS5 virtual), conversations, turns 检索: recall_memory 工具 FTS5 MATCH
L4 Session Anchors · 会话级临时记忆

V2 多步任务的关键产出锚点（文件路径、关键决策、临时文件名），通过 remember_fact / recall_fact 工具操作。会话内有效，不参与跨会话同步，防止被 trim/compact 砍掉。

📌 conv_facts

conv_id + key 联合主键 · value 纯文本或 JSON · updated_at

🤝 sub-agent 共享

子 agent 也可 recall_fact 跨子任务读取锚点，实现步骤间数据传递。

表: conv_facts 生命周期: 会话级(随会话消亡)
⚙️
记忆生命周期

从用户发送消息到记忆沉淀，完整的写入→检索→注入→维护流水线。

1

用户发送消息 → memoryBlock() 构建

L0 L1 L2 发送消息时，TaskManager.send() 调用 memoryBlock(conv) 异步构建记忆注入块： ① 加载 Memory Blocks（L0，XML 格式）； ② 取最近 3 轮用户消息拼接为 query，走 recallForInjection() 三级检索（L1）； ③ 查询知识图谱三元组（L1）； ④ 加载最近 5 条 Episodic Memory（L2）。 拼成一个 _memory: true 的 user 消息，插入 history 头部（不进 systemPrompt，保持 KV 缓存稳定）。

2

Agent 执行 → recall_memory 主动检索

L3 L1 Agent 在执行过程中可随时调用 recall_memory 工具，三级检索： Stage 1 — embedding cosine 语义召回 facts（top 20, score > 0.2）； Stage 2 — FTS5 MATCH 全文检索 history 表 + embedding 重排； Stage 3 — LIKE 关键词兜底。同时查知识图谱三元组。

3

回合结束 done → 双轨异步提取

L1 L2 applyAndPersist() 在 done 事件后并行触发两个异步提取器（不阻塞主流程）：
① extractMemories() — 发 LLM 提取原子事实 (facts ≤18字 + importance 1-10) 和知识图谱三元组 (S→P→O)。30s 超时，同会话串行化。
② extractEpisodicMemory() — 发 LLM 生成 3-5 句叙事摘要 + tags + importance。20s 超时。总对话 ≥200 字才触发。

4

去重 + 存储 → 三级去重策略

L1 提取的 facts 经三级去重后写入： ① 精确匹配（快，过滤完全相同的）； ② Jaccard 模糊（bigram token 相似度 ≥ 0.65 视为重复）； ③ Embedding 语义（cosine ≥ 0.85，最准但需异步）。 通过的写入 memories 表 + 异步生成 embedding 向量存入 memory_embeddings。

5

记忆 GC → runIdleReflection()

每 5 次 done 事件触发一次 idle reflection（纯规则，不调 LLM）： ① dedupMemories(0.65) — 全量扫描，Jaccard ≥ 0.65 的删除后来者； ② decayMemories() — weight ×= 0.95days，weight < 0.1 的连同 embedding + meta 一起删除； ③ pruneLowImportanceMemories(2) — importance ≤ 2 且从未被 recall 命中 (use_count=0) 的直接删除。

📐
记忆检索评分公式

L1 语义记忆库注入时的排序策略：scoredMemories() 对每条记忆计算加权得分。

score = importance × 0.5 + recency × 0.3 + relevance × 0.2
50%
Importance
LLM 提取时打分 1-10，归一化到 0-1。核心偏好/技术栈 = 8-10，一般习惯 = 5-7，边缘信号 = 2-4。
30%
Recency
指数衰减：e-(now - lastUsed) / 30天。30 天半衰期，被 recall 命中会刷新 lastUsed。
20%
Relevance
Embedding cosine 相似度（0-1）。无 embedding 接口时回退 LIKE 匹配（命中=0.5，不命中=0）。
🔍
recall_memory 三级检索管线
STAGE 1
Embedding Cosine

对 memories 表的所有存储向量做 cosine top-K。score > 0.2，取 top 20。命中 ≥ 3 条则返回。同时 touch 权重。

→
STAGE 2
FTS5 + Embedding Rerank

Stage 1 不足 3 条时，对 history 表 FTS5 MATCH 召回 30 条，实时算 embedding 重排。+ LIKE 搜 memories 表。

→
FALLBACK
Recent-N

无 query 或检索全空时，直接取最新 N 条 memories（按 created_at DESC）。保证总有内容注入。

策略目标表机制触发条件延迟
Embedding Cosine memories + memory_embeddings 768 维 Float32Array，暴力 O(n) cosine 有 query + 有 embedding 数据 ~50ms (3607 条)
FTS5 MATCH history SQLite FTS5 全文索引，rowid DESC Stage 1 不足 或 recall_memory 兜底 ~5ms
LIKE 模糊 memories content LIKE %q%，importance DESC 排序 无 embedding 接口时 ~10ms
Recent-N memories created_at DESC LIMIT N 无 query / 全空 ~2ms

Agent 记忆工具链
🔍

recall_memory

语义搜索历史记忆。三级检索管线：embedding cosine → FTS5 + rerank → 关键词兜底。同时查知识图谱三元组。

readOnly L1 + L3
🔄

memory_replace

覆盖更新核心记忆块（L0）。指定 block 名（user_profile / project_context / active_goals），完整替换内容。persona 块只读。

write L0
➕

memory_append

向核心记忆块末尾追加内容（不覆盖）。超 char_limit 时从头部截断。

write L0
📌

remember_fact

保存会话级 KV 锚点（L4）。key 在 conv 内唯一，value 纯文本或 JSON。防止被 trim/compact 砍掉。

📖

读取会话级锚点。key 不存在返回 "(无此 key)"。子 agent 也可调用，跨子任务共享。

🧬

分析 200 轮历史 + 200 条记忆，LLM 生成用户做事风格画像（沟通风格/技术栈/工作偏好/决策模式/替身指令），写入 persona block。

跨引擎记忆注入

记忆系统的输出 memoryBlock 会被注入到三种引擎的不同位置：

引擎注入位置机制记忆生效范围
Direct (Kaios) history 头部 user msg _memory: true 标记，不进 systemPrompt 当前轮 + reactive trim 管理
Claude Code --append-system-prompt 记忆块拼到 CLI flag 尾部 整个 CLI session
Codex prompt 前缀 记忆块 prepend 到用户输入前面 单次 codex exec 调用
♻️
去重与衰减策略
🔀

三级去重 (extractMemories 写入时)

  • 精确匹配 — 完全相同直接跳过
  • Jaccard 模糊 — bigram token 相似度 ≥ 0.65。先 norm（去前缀/括号/空格），再取 max(包含比, bigram Jaccard)
  • Embedding 语义 — cosine ≥ 0.85。异步执行，全失败也回退文字去重

dedupMemories(0.65) 在 idle reflection 时再次全局扫描。

📉

指数衰减 (decayMemories)

  • 公式：weight ×= 0.95^days
  • 删除阈值：weight < 0.1 → 连同 memory + embedding + meta 一起删
  • 刷新机制：recall_memory 命中时 touchMemoryUsed() 更新 last_used + use_count
  • 低价值清理：importance ≤ 2 且 use_count = 0 → 直接删

每 5 次 done 事件触发一次 idle reflection。
