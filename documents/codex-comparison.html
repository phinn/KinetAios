KinetAios vs Codex CLI

竞品深度对比：本地多引擎 Agent 仪表盘 vs OpenAI 官方编码智能体
KinetAios — 15,500+ 行 TS · 4 引擎 · 14 SQLite 表 Codex CLI — Rust 重写 · 60+ crate · Apache-2.0
数据来源：openai/codex @ main · KinetAios 代码库 @ latest · 生成于 2026-08
01架构哲学
两者从不同方向切入"AI 编码 Agent"问题域——KinetAios 是自研引擎+多引擎编排的桌面仪表盘，Codex CLI 是 OpenAI 官方出品、Rust 重写的 TUI/Headless 编码智能体。

KinetAios 架构

  • 🖥️ Electron 三进程（Main / Preload / Renderer）
  • 🎨 Vanilla TS + HTML/CSS（无前端框架）
  • ⚙️ TypeScript 引擎层 engines.ts
  • 🔄 DirectV2: Plan → Execute → Verify → Judge
  • 🧠 三层记忆：Core Blocks + LTM + Episodic
  • 💾 SQLite (better-sqlite3 + FTS5) · 14 表
  • 🔌 插件 SDK + MCP Remote + Team
  • 🌐 4 语言 i18n · 语音 WebSocket

Codex CLI 架构

  • 🦀 Rust 全栈重写（codex-rs workspace）
  • 📐 60+ Cargo crate，高度模块化
  • ⌨️ TUI 交互模式 + codex exec headless
  • 🔄 SQ/EQ 模式（Submission Queue / Event Queue）
  • 🧠 Phase 1/2 记忆管线（rollout extraction → consolidation）
  • 💾 SQLx + libsqlite3-sys（WAL 模式）
  • 🔌 MCP client + Skills + Hooks + Agent Identity
  • 🔐 Linux Landlock + macOS Seatbelt + Windows sandbox
⚖️
判断： KinetAios 走"广度优先"路线——多引擎编排+富 UI+记忆系统一体化； Codex 走"深度优先"路线——单一引擎但把沙箱/安全/性能做到极致。 路线不同

03沙箱与安全模型
这是 Codex 最大的架构优势——OS 级强制隔离 vs KinetAios 的应用层逻辑控制。
KinetAios

🔧 应用层三级沙箱

  • readOnly — 只读，不执行写操作
  • workspaceWrite — 仅工作目录可写
  • fullAccess — 完全访问（默认）
  • Shell 确认桥：confirm-request → Renderer modal → confirm-response
  • approval: 'never' 可短路确认
  • 跨平台 CLI spawn：.cmd 走 shell: true（CVE-2024-27980）
Codex CLI

🛡️ OS 级强制沙箱

  • Linux: landlock crate — 内核级文件访问控制
  • macOS: Seatbelt (sandbox-exec) — 系统级限制
  • Windows: WindowsSandboxLevel 枚举（protocol 层定义）
  • 独立 linux-sandbox + sandboxing + process-hardening 三 crate
  • execpolicy crate — 命令执行策略引擎
  • shell-escalation — 提权检测与拦截
  • 网络隔离：sandbox 内可限制域名/IP
🛡️
安全差距明显： Codex 的沙箱是 OS 内核级强制隔离，即使 Agent 被注入恶意指令也无法逃逸。 KinetAios 的三级沙箱依赖应用层逻辑，fullAccess 下 Agent 可执行任意命令。 Codex 大幅领先

06差距分析 — KinetAios 还差什么
基于源码级调研，以下是 KinetAios 相对 Codex CLI 的关键差距，按优先级排序。
  • 1. OS 级沙箱隔离 关键差距
    Codex 使用 Linux Landlock（内核级）、macOS Seatbelt、Windows Sandbox 做进程级强制隔离， 外加 execpolicy 命令策略引擎 + shell-escalation 提权检测。 KinetAios 仅靠应用层三级沙箱（readOnly/workspaceWrite/fullAccess），fullAccess 下无任何 OS 级保护。
    建议：集成 landlock（Linux）或研究 Windows AppContainer 做进程隔离。
  • 2. Hooks / 生命周期钩子 功能缺失
    Codex 有完整的 Hooks 系统（hooks crate + schema/generated），支持管理员级 allow_managed_hooks_only。用户可在 pre-session / post-turn / pre-tool 等生命周期点注入自定义逻辑。 KinetAios 无任何 Hook 机制。
    建议：在 TaskManager 或 AgentLoop 中加入 lifecycle hook 注册点。
  • 3. Process Hardening 安全差距
    Codex 有独立 process-hardening crate 做进程加固（禁用危险 syscalls、限制 fd 等）。 KinetAios 的 Electron 进程无任何加固。
    建议研究 Electron 的 --no-sandbox 反向加固或 Node.js policy 机制。
  • 4. Skills 目录规范 生态差距
    Codex 有 .codex/skills/ 目录约定 + SKILL.md 规范 + core-skills crate。 每个 Skill 是一个带脚本+提示词的自包含单元。KinetAios 有 Plugin SDK 但缺少 Skills 式的轻量约定。
    建议：在 Plugin SDK v2 基础上增加 skills/ 目录约定 + SKILL.md frontmatter 规范。
  • 5. 记忆引用追踪（MemoryCitation） 体验差距
    Codex 在 memories/read crate 中实现 MemoryCitation 解析——Agent 回复中引用了哪些记忆可追踪。 KinetAios 注入记忆后无法追踪哪些记忆被实际使用。
    建议：在 applyEvent 中增加 citation 解析，或用 [mem:ID] 标记法。
  • 6. Cloud / CI 集成 场景差距
    Codex 有 cloud-tasks + cloud-config + backend-client crate， 支持 Codex Web 云端执行 + GitHub PR 集成。KinetAios 纯本地。
    建议：设计可选的 cloud-relay 模块，支持远程任务派发。
  • 7. ext/ 扩展模块体系 架构参考
    Codex 有完整的 ext/ 目录：agent / connectors / extension-api / goal / git-attribution / guardian / image-generation / items / memories / mcp / skills / web-search。 每个是独立 crate，可按需编译。KinetAios 的工具和扩展耦合在 tools.ts 和引擎层中。
    建议：将 tools.ts 拆分为独立模块，研究 ES Module 动态加载。
07KinetAios 领先项 — Codex 做不到的
  • A. 多引擎编排 独有能力
    4 引擎切换 + Pipeline 多阶段串联。Codex 仅支持 OpenAI Responses API（虽可通过 base_url 接其他 provider）。
    这意味着 KinetAios 可以"用 Claude 规划 → 用 GLM 执行 → 用 Codex 验证"，Codex CLI 做不到。
  • B. DirectV2 四阶段循环 架构优势
    Plan → Execute → Verify → Judge 四阶段。Codex 是标准 ReAct loop（Thought → Action → Observation），无独立 Verify/Judge 阶段。
  • C. Agent Team 持久化 独有能力
    ≤8 成员的持久化 Team（spawn_team / broadcast / send / close），每个 member 有独立 history。 Codex 虽有 MultiAgentMode 枚举和 sub-agent session，但不是一等公民的 Team API。
  • D. 富 GUI 仪表盘 形态优势
    Electron + Vanilla TS 的完整仪表盘：多会话并行、Markdown 渲染、Monaco 代码编辑器、Memory Graph 可视化、Arena 对比面板。 Codex 是 TUI（终端界面），无 GUI。
  • E. ContextPolicy 精调系统 深度优势
    6 字段 per-engine 上下文策略 + hifi mode。Codex 的记忆注入是单一路径（developer-instruction），无 per-engine 策略。
  • F. Cron 定时任务 独有能力
    cron_tasks 表 + 调度器。Codex 无内置 Cron。
  • G. 文件快照回溯 独有能力
    pre-write snapshot + restore。Codex 有 apply-patch 但无快照回溯。
  • H. 4 语言国际化 + 全局热键 + 语音 体验优势
    en / zh-CN / zh-TW / ja 四语言 + 全局热键 Quick Panel + Doubao Realtime 语音 WebSocket。 Codex 英文 TUI + 无全局热键（Realtime API 有 audio 支持但非交互式语音对话）。
