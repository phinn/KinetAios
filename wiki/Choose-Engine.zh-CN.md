# V1 / V2 / V3 引擎怎么选？

KinetAios 内置三个 Kaios 引擎，每个会话可独立切换。三个引擎用的是**同一个模型、同一套工具**，区别在于**工作方式**——选对引擎，同样的任务耗时和效果能差一倍以上。

## 30 秒速查表

| 你的任务 | 选 |
|---|---|
| 问答、翻译、写作、读文件、改一个文件的小问题 | **V1** |
| 需要控制成本、想看清每一步在干什么 | **V1** |
| 多文件联动改代码、带验证的重构、多步数据处理 | **V2** |
| 数据分析、报表统计、跨表交叉对比 | **V3** |
| 不确定用哪个 | **V3**（它会自动判断任务难度） |

---

## V1（Direct）— 轻快直连型

**工作方式**：单线 ReAct 循环，模型直接调工具，每一步实时可见。上下文策略轻量，响应最快、token 消耗最低。

**适合**：
- 问答、解释、翻译、写文案写邮件
- 读某个文件、查一段代码、做小修改
- 一问一答式的连续对话
- 想精确控制成本和流程的时候

**不适合**：
- 跨很多文件的重构（容易在长对话里丢前面的发现）
- 多步骤数据处理（中间结果靠对话记忆，长了会被截断）

**小技巧**：让 V1 做数据分析时，可以用 `/data-analysis` 手动加载数据分析工作法，能明显减少"心算报数"类错误。

---

## V2 — 先规划再执行型

**工作方式**：复杂任务先进入**规划阶段**（只读探查，产出分步计划），再按计划逐步执行，每步可带验证命令（类型检查 / 测试），失败自动重试（每步最多 3 次，最多重新规划 2 次）。

**适合**：
- 多文件联动的代码修改和重构
- 改完需要跑测试/lint 验证的开发任务
- 多步数据处理、跨文件统计（中间结果强制落盘到记忆或临时文件，抗截断）
- 你想**先看到计划再放行执行**的任务

**不适合**：
- 简单问答、单文件小改动（会白走规划流程，慢且贵）
- 大规模多文件并行任务（V2 是串行逐步执行）

**小技巧**：V2 对太简单的任务会自动退化为普通模式，不用担心"杀鸡用牛刀"——但如果你已经知道任务很简单，直接用 V1 更快。

---

## V3 — 自适应流水线（推荐默认）

**工作方式**：系统先用零成本规则给任务分级，自动走三条路径之一：

- **fast**：读文件、查文档、简单问答 → 单轮直出，零额外开销
- **std**：修 bug、写功能、**数据分析** → 多轮工具执行
- **deep**：跨文件重构、架构级变更 → 自动规划成 DAG 任务图，无依赖的步骤**并行执行**，自带验证门

**适合**：
- **数据分析 / 报表 / 统计**——V3 内置分析工作法：先摸数据结构再下结论、计算交给 python/sqlite 不心算、中间结果落盘、结论必须可溯源、关键数字交叉验证。状态栏出现「📊 分析模式」即已生效
- 不确定复杂度的任务（交给它自动路由）
- 复杂重构（deep 路径的并行 + 验证是三个引擎里唯一有的）

**不适合**：
- 需要精确控制每一步的高级玩法（V1 更透明）
- 极度追求最低成本的一问一答（fast 路径其实很省，但 V1 更省一点）

## 常见场景对照

| 场景 | 推荐引擎 | 原因 |
|---|---|---|
| "帮我看看这个报错" | V1 或 V3 | 单点问题，快就完了 |
| "把这个功能从 A 文件挪到 B 文件，改完跑下测试" | V2 或 V3 | 有验证需求的代码改动 |
| "分析这两个 CSV 的差异，出个对比报告" | V3 | 分析工作法 + 中间产物落盘 |
| "整个项目从 JS 迁移到 TS" | V3（deep） | 唯一支持 DAG 并行 + 验证门 |
| "翻译这段话" | V1 | 不需要任何工具编排 |
| "先给我个方案，我确认了再动手" | V2 | 规划阶段天然就是"先出计划" |

## 注意事项

- **切换引擎 = 清空跨引擎上下文**：三个引擎的历史格式不互通，任务做到一半别换引擎
- 三个引擎共享同一套模型配置、MCP 工具和记忆系统，切换不需要重新配置
- 数据文件（csv/xlsx/db）出现在任务描述里时，V3 会自动进入分析模式；V1 建议配合 `/data-analysis` 使用
