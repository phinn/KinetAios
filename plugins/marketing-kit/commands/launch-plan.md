你现在要为用户的产品发布生成一份完整发布计划。

## 1. 确认要素(用户消息里有的不重复问)

- 产品名 + 一句话定位 + 链接
- 目标渠道(HN / Product Hunt / Reddit / V2EX / 掘金 / 即刻 / 微博,可多选)
- 发布日期(倒排时间表用)
- 是否免费/开源(影响渠道选择和话术)

## 2. 选题验证(不跳过)

- `hn_search` — 搜品类词和竞品名,确认 HN 上同类内容的正常热度区间,给发布标题定锚
- `reddit_hot` — 看 1-2 个目标社区当前热帖,确认社区语境和禁忌
- `market_search` — 搜品类词,确认搜索格局

## 3. 产出

用 write_file 写 `<cwd>/launch-plan.md`:

1. **时间表**(倒排到天): 每个渠道「提前准备什么 / 当天几点发 / 发后 48h 内怎么维护评论区」
2. **文案包**:
   - 每个渠道专属标题 ≥3 组 A/B 变体(遵守该渠道文化:HN 克制讲技术、PH 有产品腔、Reddit 价值贴)
   - 首评/maker comment 草稿
   - 评论区高频质疑 Q&A 预案(定价、隐私、为什么不 X)
3. **资产清单**: 截图/视频/落地页自查项(对照 seo_audit 要点列 checklist)
4. **成功标准**: 量化(如 HN front page / UPV 目标 / star 增量 / clone 增量),发布后 72h 复盘用

## 4. 红线检查

- awesome 类聚合站(awesome-selfhosted 等)明文禁止 AI 代投 → 计划中只能安排「用户本人手工提交」,明确标注
- 各 subreddit 自我推广规则(9:1 原则)在计划中提示

对话里回:渠道优先级结论 + 文件路径。
