# v4.2.6 — HTML 卡片宽度回路 / 首图规格不再死在压缩里 / 技能目录按项目加权 / ASR 可配端点

## 新功能
- **聊天流 html/md 链接应用内预览** — 此前在对话里点 `.html`/`.md` 链接只能丢去系统浏览器，看到的是源码或空白页。现在 html 走应用内 `<webview>`（`partition=persist:files`，与文件面板同会话隔离）直载；md/txt/rst 走 `fetch-text` IPC 取原文后用聊天流同款 renderMarkdown 渲染。`fetch-text` 带 SSRF 硬闸：协议白名单、仅 GET、30s 超时、512KB 上限、15 跳重定向，私网与云元数据 IP 黑名单而**逐跳复检**。非 html/md 链接和带修饰键的点击仍走系统浏览器；Esc / 点遮罩 / ✕ 关闭
- **语音转写可配自定义 ASR 端点，失败不再静默** — 此前转写硬编码用主 provider 的 `baseURL` 打 `/audio/transcriptions`，Anthropic 协议端点没有这个路径 → 404 `REQUESTED PATH not found`，而 VAD 循环把错误吞掉，表现就是「按住说话永远不出字」。设置面板新增「语音转写（ASR）」段（`baseURL`/`apiKey`/`model`，加密存储、key 不回显），留空沿用主 provider；转写失败会弹出点明根因的提示（30s 节流，不打断 VAD 循环，配置改好即恢复）；兼容模式的失败同样可见；中英日韩四语文案

## 修复
- **HTML 卡片宽度无限变宽** — 用户报「对话里显示的 html 页面宽度一直不停地变宽」，是上一版窄卡判定的自伤。内层量内容宽用 `body{width:fit-content}`，而 `fit-content = min(max-content, 可用宽)`：一旦 iframe 被收窄，**流体内容量回来的就是宿主刚给它的那个宽度**（实测 iframe 362 时报 362），宿主再按 `w+2` 写回 → 每轮 +2px 一路顶到满宽。任何一次「首次上报发生在布局完成前」（卡片刚插 innerHTML、容器暂窄）都会把卡片打进窄态再开始爬。真实 Chromium 复现：旧 386 → 398 → 414 → … → 524（每 200ms，2.4s 内 76 次上报），新恒定为满宽、4 次上报后自行停止。改法：量宽改 `max-content`（内在宽，与可用宽无关 —— 同一份文档在 frame=362/700 下都报 624，写回的宽度不可能让下次测量变大，数学上成不了环）；判定抽成纯函数 `viz-width.ts` 并加「饱和闸」（上报值 ≥ 当前 iframe 宽即视为回声，一律铺满、绝不据此收窄），迟滞 0.78/0.92 保留，卡片宽夹在父容器内且不小于 160；宿主写尺寸前先比对、同值不写（同值重写也会触发内层 resize → 再上报）。新增 9 例回归测试与 `scripts/diag-viz-loop.js` 复现脚本
- **首图规格不再死在压缩里** — 会话 `b580efbe`（KinetBrief）里用户连说 5 次「不对」，查下来不是模型不理解首图，是规格在传递途中被丢掉。`summarize` 的 transcript 把非 text 的 content part 映射成空串，而 11-24 00:06 那条带图消息在库里是 **490,828 字符**、transcript 上限只有 16K —— 一张图把整段经历挤进「…[截断]」，摘要只能写「无」。该会话 33 次压缩共折叠 174 个多模态条目；11-23 全天 16 次压缩摘要里「紫」出现 **0 次**，所以用户说「蓝色不对」时 agent 手上根本没有紫底这条规格。现在图片降级为 `[图片 文件名]`（带 name 便于回找）、transcript 上限 16K → 24K、摘要新增第 7 栏**【已验收规格】**（色值/尺寸/文案/参考路径保原值、禁止概括，用户否决过的做法也记），且合并摘要时该栏**只增不减**
- **技能目录被自己的产出撑爆，简介全被抹成 0 字** — 203 个自有技能：22 字简介需要 9943 字符、12 字需要 7923，预算只有 5541，cap 一路降到 0，目录里只剩裸名字。而注入语写的是「当任务与下列某项**描述**匹配时必须 load_skill」—— 描述不存在，这句话就无法执行；该会话 700+ 次工具调用只 `load_skill` 了 1 次。改为按边际价值分三层：手写技能永远带简介；蒸馏技能里「本项目蒸馏出来的」（`skill_origin ⋈ conversations.cwd`）和「用过的」（`load_skill > 0`）带简介，其余只列名（名字仍全部可见，可按名取回）。KinetBrief 下命中 13 条，正是 `ios-sim-shot-firstimg` / `promo-slides-ffmpeg` / `asc-video-restore-fix` / `asc-screenshot-restyle` 这些正解。注入语补硬规则：动手前先扫一遍名字，沾得上就先 load_skill，不许凭印象直接写脚本
- **技能淘汰补上「无溯源目录」** — `findArchiveCandidates` 的长期未用判据写成 `origin && loads===0 && age>=14`，而 `skill_origin` 是 11-19 才加的账本，之前落的 **48 个蒸馏目录**永远没有来源记录，于是拿到免死金牌（真实归档至今只收过 6 条，且全是正文 <200B 的空胎）。改为不要求溯源：无溯源目录同样在 `distilled/` 下，14 天 0 加载即可归档（只是同卷 rename 到 `.archive/`，随时可 restore，不丢内容）
- **测试不再污染真实技能库** — `80-skill-distill` 没隔离 HOME，每跑一次就往用户真实的 `~/.kinetaios/skills/distilled/` 写两个假技能（正文 8B/59B），随后真实的归档清扫把它们当空胎收走 —— 11-19/20/21 连续三天各归档一次，会话里还冒出「🗄 已归档 2 个失效技能」。现在切临时 HOME 并在结束时还原
- **缺口判断只认对话内容** — `loadTurns` 把「只有 `turn/error`/`turn/status`/`tool/call`」的事件轮算成缺轮。补库后这类孤儿轮共 **42 个**（散在 24 个会话），它们的 `turn_id` 在 `turns` 表里从来没有过 → 这 24 个会话永远「有洞」，每次打开都全量重放事件（最贵 27,145 条，实测 72,178 条读完 + 逐条 JSON.parse = 242ms），重建结果除这几轮外全被丢弃；UI 里还多出 prompt 为空的报错卡，连「重试」都被 `!prompt.trim()` 挡掉。改为只数 `user/message`・`assistant/message` 两类（同为 7 天保留，真丢的轮照样照得出来），新口径下 24 → **0** 个会话
- **超时判定只看结果头部** — `toolOutcomeOf` 的 `includes('⏳ 超时')` 是全串匹配，把「正文引用了这段文案」的成功调用判成失败：11-20 17:23 的 `codemode` 返回是一段提交正文，「⏳ 超时」在第 2096 字符处，首行明明是「✅ 完成。」却被记成 error。超时文案永远在结果最前面，改为只扫前 200 字符
- **远端删除加机械闸** — 11-23 14:49 想清 en-US 里 FAILED 的 appPreview，脚本遍历整个集合逐个 DELETE，两条都 204 —— 唯一能用的原版一起被删。语义判断机器做不对，能做的只有「删之前让人看一眼」：`agent-policy` 加内置高危 ask（不依赖策略文件），对 ASC 素材/版本/内购的 DELETE、以及 `for`/`while` 里的 DELETE 一律强制 confirm，单个明确目标的 DELETE 不拦
- **新增技能 `find-master-asset`** — 用户说「用我之前那个 / 原版 / 和 X 一样」时先全盘 + artifacts + `git log --diff-filter=A` + 记忆定位母版，禁止重造；找不到就报候选让人选，不许猜。那次的原版视频 10-16 就躺在 `~/Documents/kinet/artifacts/kb_preview_video/` 里，agent 花了 7 小时重造它

**English**

## New Features
- **In-app preview for html/md links in the chat feed** — clicking an `.html`/`.md` link in a conversation used to hand it to the system browser, where you got raw source or a blank page. html links now render in an in-app `<webview>` (`partition=persist:files`, same isolated session as the files pane); md/txt/rst are fetched through a `fetch-text` IPC and rendered with the chat feed's own renderMarkdown pipeline. `fetch-text` carries an SSRF hard gate: protocol allowlist, GET only, 30s timeout, 512KB cap, 15 redirects, and private-network / cloud-metadata IP blocklists re-checked **on every hop**. Non-html/md links and modified clicks still go to the system browser; Esc / backdrop click / ✕ closes
- **Configurable ASR endpoint, and transcription failures are no longer silent** — transcription was hardcoded to POST `/audio/transcriptions` on the main provider's `baseURL`; Anthropic-protocol endpoints have no such route, so calls returned 404 `REQUESTED PATH not found` while the VAD loop swallowed the error — the symptom was "hold to talk and nothing ever appears". Settings gains a Voice Transcription (ASR) section (`baseURL`/`apiKey`/`model`, encrypted at rest, key never echoed); leave it empty to inherit the main provider. Failures now raise a toast naming the root cause (throttled to 30s, does not break the VAD loop, recovers as soon as the config is fixed), including in compatibility mode; copy added in EN/ZH/JA/KO

## Fixed
- **HTML cards growing wider forever** — reported as "the html page shown in the conversation keeps getting wider"; self-inflicted by the previous narrow-card logic. The inner document measured content width with `body{width:fit-content}`, and `fit-content = min(max-content, available)`: once the iframe was narrowed, **fluid content measured back exactly the width the host had just given it** (measured 362 at frame 362), and the host wrote back `w+2` → +2px per round-trip all the way to full row. Any first report that lands before layout settles (card just injected into innerHTML, temporarily narrow container) pushed the card into the narrow state and started the climb. Reproduced in real Chromium: old 386 → 398 → 414 → … → 524 (every 200ms, 76 reports in 2.4s); new stays at full width and stops after 4 reports. Fix: measure with `max-content` (the intrinsic width, independent of available space — the same document reports 624 at both frame=362 and 700, so a write-back can never enlarge the next measurement and the loop is mathematically impossible); the decision is extracted into the pure `viz-width.ts` with a saturation guard (a report ≥ the current iframe width is an echo — go full width, never shrink from it), keeping the 0.78/0.92 hysteresis, clamping the card to its parent and to a 160px floor; and the host compares before writing (rewriting an identical value still fires an inner resize → another report). 9 regression tests plus a `scripts/diag-viz-loop.js` reproducer
- **Hero-image specs no longer die in compaction** — in conversation `b580efbe` (KinetBrief) the user said "still wrong" five times; it was not that the model misunderstood the brief, the specification was being dropped in transit. `summarize` mapped non-text content parts to empty strings, and the image message from 2026-11-24 00:06 is **490,828 characters** in the store against a 16K transcript cap — one image pushed the whole history into "…[truncated]" and the summary could only say "none". That session's 33 compactions folded 174 multimodal entries; across 16 compactions on 11-23 the word "purple" appeared **zero times**, so when the user said "the blue is wrong" the agent had no purple-background spec at all. Images are now downgraded to `[图片 文件名]` (filename kept for lookup), the transcript cap goes 16K → 24K, the summary gains a seventh section **【已验收规格】/ Accepted Specs** (colors, sizes, copy and reference paths kept verbatim, no paraphrasing; rejected approaches recorded too), and merging summaries may only add to that section, never drop entries
- **The skill catalog was being crushed by its own output** — with 203 user skills, 22-character intros need 9,943 characters and 12-character intros 7,923 against a 5,541 budget, so the cap fell to 0 and the catalog degraded to bare names. The injected instruction says "when a task matches one of the **descriptions** below, load that skill first" — with no descriptions that sentence cannot be executed; that session made 700+ tool calls and called `load_skill` exactly once. Intros are now tiered by marginal value: hand-written skills always keep theirs; distilled skills keep theirs when distilled *from this project* (`skill_origin ⋈ conversations.cwd`) or when actually used (`load_skill > 0`); the rest show name only (all names remain visible and loadable). Under KinetBrief this surfaces 13 entries — exactly the right answers (`ios-sim-shot-firstimg`, `promo-slides-ffmpeg`, `asc-video-restore-fix`, `asc-screenshot-restyle`). The instruction also gained a hard rule: scan the names first, load anything relevant, never improvise a script from memory
- **Skill eviction now covers directories with no provenance** — the "long unused" predicate was `origin && loads===0 && age>=14`, but `skill_origin` only shipped on 11-19, so **48 distilled directories** had no provenance row and were immortal (only 6 items were ever archived, all empty shells under 200B). Provenance is no longer required: a directory without it sits in `distilled/` just the same, and 14 days at zero loads is enough to archive (a same-volume rename into `.archive/`, restorable at any time, nothing lost)
- **Tests no longer pollute the real skill library** — `80-skill-distill` did not isolate HOME, so every run wrote two fake skills (8B/59B bodies) into the user's real `~/.kinetaios/skills/distilled/`, where the real archive sweep then collected them as empty shells — three days in a row (11-19/20/21), with "🗄 archived 2 stale skills" surfacing in conversations. It now switches to a temp HOME and restores it afterwards
- **Hole detection now counts conversation content only** — `loadTurns` treated turns carrying only `turn/error`/`turn/status`/`tool/call` as holes. After the library restore there were **42** such orphan turns across 24 sessions whose `turn_id` never existed in `turns` → those sessions were permanently "holey" and replayed every event on each open (up to 27,145 events; measured 72,178 events read and parsed = 242ms), with the rebuilt rows discarded apart from those few turns; the UI also grew error cards with an empty prompt whose Retry was blocked by `!prompt.trim()`. Only `user/message` and `assistant/message` count now (both retained 7 days, so genuinely lost turns are still detected): 24 → **0** sessions
- **Timeout detection only looks at the head of the result** — `toolOutcomeOf` used a whole-string `includes('⏳ 超时')`, which marked successful calls as failures when the body merely quoted that wording: the `codemode` result at 17:23 on 11-20 was a commit message containing it at character 2,096 with a first line of "✅ 完成。", yet was recorded as an error. Timeout wording always sits at the very start, so only the first 200 characters are scanned
- **Mechanical gate on remote deletions** — at 14:49 on 11-23 a script meant to clear FAILED appPreviews iterated the whole collection and DELETEd each, both returning 204 — taking the only working original with it. Machines cannot make that semantic call, so the only thing left is to make a human look first: `agent-policy` now ships a built-in high-risk ask (independent of the policy file) that forces confirmation for ASC asset/version/IAP DELETEs and for DELETEs inside `for`/`while` loops, while a single DELETE with an explicit target passes through
- **New skill `find-master-asset`** — when the user says "use the one I had before / the original / same as X", locate the master asset first (whole-disk search + artifacts + `git log --diff-filter=A` + memory) and never rebuild it; if it cannot be found, list candidates for the user to pick rather than guessing. The original video had been sitting in `~/Documents/kinet/artifacts/kb_preview_video/` since 10-16 while an agent spent 7 hours recreating it
