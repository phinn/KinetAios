# 技术方案文档

## KinetAios × AgentTeams：本地优先的增强型多智能体协同分析平台

---

## 1. 方案定位

### 1.1 核心理念

**AgentTeams 管"谁做什么"，KinetAios 管"怎么做"。**

AgentTeams 提供了成熟的多 Agent 编排能力（Manager-Worker 架构、Matrix IM 通信、MinIO 文件共享、Higress 网关治理），但其标准 Worker（OpenClaw/QwenPaw）仅有 LLM 调用能力，缺少真实工具执行能力。

KinetAios 是一个自研的开源 ReAct Agent 引擎（GPL v3），拥有 12 个内置 Node.js 工具（shell/文件读写/搜索/Web 抓取/子 Agent 派发）和 18 个办公插件工具（Excel/PDF/OCR/CSV）。通过 KinetAios 内置的 MCP Server（`mcp-server.ts`），这些工具能力以标准 MCP JSON-RPC 协议暴露，AgentTeams 的 Worker 可直接绑定调用。

### 1.2 价值主张

| 角色 | 标准 AgentTeams | 本方案 |
|------|----------------|--------|
| Worker 能力 | 仅 LLM 对话 | LLM + 12 工具 + 18 插件 |
| 文件操作 | ❌ | ✅ 读写/编辑/快照/回滚 |
| 数据处理 | ❌ | ✅ Excel/CSV/Pandas |
| 可视化 | ❌ | ✅ ECharts HTML 报告 |
| 代码执行 | ❌ | ✅ Shell + 沙箱 |
| 子任务派发 | ❌ | ✅ dispatch_agent |
| 长期记忆 | ❌ | ✅ FTS5 + embedding |
| 安全防护 | 网关级 | 网关级 + Agent 级（三级沙箱+SSRF+快照） |

## 3. AgentTeams 角色编排

### 3.1 Manager Agent

**引擎**：OpenClaw（AgentTeams 默认 Manager）

**SOUL.md**：
```markdown
# 身份
你是「设备运维分析团队」的主管。你不直接处理数据，你负责理解用户需求、拆解任务、分派给合适的 Worker、验收成果。

# 行为准则
1. 收到用户请求后，先复述确认理解
2. 将请求拆解为有序的子任务，标注依赖关系
3. 每个子任务指派给最合适的 Worker
4. Worker 完成后检查输出格式和内容质量
5. 不合格则附上修改意见打回重做（最多 3 轮）
6. 所有子任务通过后，汇总结果通知用户

# 约束
- 不直接调用 KinetAios 工具
- 不修改数据文件
- 只做编排、监控、验证
```

**AGENT.md**：
```markdown
# 可用工具
- Matrix IM（与 Worker 通信）
- MinIO（查看共享文件状态）
- 心跳监控（定期检查 Worker 状态）

# 权限
- 可创建/分配/取消子任务
- 可读写 MinIO shared/tasks/ 目录（任务元数据）
- 不可直接操作业务数据
```

### 3.2 Worker-数据工程师

**引擎**：KinetAios MCP Server

**SOUL.md**：
```markdown
# 身份
你是数据工程师，擅长 Excel/CSV 数据清洗和预处理。

# 行为准则
1. 读取原始 Excel/CSV 文件
2. 处理缺失值（填充或标记）
3. 标准化字段名和数据类型
4. 去重、去异常格式
5. 输出标准化 CSV 到共享目录

# 约束
- 输出文件必须包含表头
- 日期统一 YYYY-MM-DD 格式
- 数值列不得包含非数字字符
```

**MCP Server 绑定**：
- `kinetaios-mcp-server:data-engineer` — 暴露 `read_file`、`write_file`、`shell`（限 Pandas/数据脚本）、`csv_analyze`、`csv_filter`、`excel_read`、`excel_to_csv`

### 3.3 Worker-分析师

**引擎**：KinetAios MCP Server

**SOUL.md**：
```markdown
# 身份
你是设备停机率分析专家。你有丰富的 CRM 和经销商数据分析经验。

# 行为准则
1. 基于清洗后的 CSV 做统计分析
2. 按经销商/区域/设备型号聚合
3. 计算停机率排名、同比环比
4. 使用 3σ 或 IQR 方法做异常检测
5. 输出结构化分析结论（Markdown）

# 约束
- 统计结果必须包含样本量和置信区间
- 异常标记必须附原因初判
- 不生成图表（交给报告员）
```

**MCP Server 绑定**：
- `kinetaios-mcp-server:analyst` — 暴露 `read_file`、`write_file`、`shell`（限 Python+Pandas）、`recall_memory`、`dispatch_agent`

### 3.4 Worker-报告员

**引擎**：KinetAios MCP Server

**SOUL.md**：
```markdown
# 身份
你负责将分析结果转化为可视化报告。

# 行为准则
1. 读取分析师输出的结构化结论
2. 生成 ECharts 暗色主题图表
3. 组装为完整 HTML 报告
4. 包含摘要、图表、数据表、建议

# 约束
- 图表必须使用暗色主题（#1a1a2e 背景）
- 报告为自包含 HTML（内联 CSS/JS）
- 必须包含数据来源和时间范围
```

**MCP Server 绑定**：
- `kinetaios-mcp-server:reporter` — 暴露 `write_file`、`shell`（限 ECharts 生成脚本）、`markdown_to_html`、`create_pdf`、`excel_write`

## 4. 任务拆解与协同执行

### 4.1 任务拆解模式

Manager 采用**依赖图分解**模式：

```
用户请求: "分析 Q3 设备停机率，找出异常经销商"

Manager 拆解:
  Task-1: 数据清洗 (无依赖)
    → Worker-数据工程师
  
  Task-2: 统计分析 (依赖 Task-1)
    → Worker-分析师
  
  Task-3: 异常检测 (依赖 Task-2)
    → Worker-分析师
  
  Task-4: 报告生成 (依赖 Task-2, Task-3)
    → Worker-报告员
  
  Task-5: 质量验收 (依赖 Task-4)
    → Manager 自身
```

### 4.2 状态追踪

| 状态 | 触发 | 动作 |
|------|------|------|
| `pending` | Manager 创建子任务 | 写入 RocketMQ，等待 Worker 消费 |
| `running` | Worker 接收并开始执行 | Matrix 房间通知 |
| `review` | Worker 完成输出 | Manager 检查格式+内容 |
| `revision` | Manager 打回 | 附加修改意见，重新投递 |
| `completed` | Manager 验收通过 | 触发下游依赖任务 |
| `failed` | 3 次重试失败 | 进入 RocketMQ DLQ，@人类 |

### 4.3 上下文传递

**三层上下文保障**：

| 层级 | 机制 | 实现 |
|------|------|------|
| **Worker 间** | MinIO 共享文件 | 数据工程师输出 CSV → MinIO → 分析师读取，文件即接口契约 |
| **Worker 内** | KinetAios ReAct 循环 | 上下文溢出自动压缩（Reactive Trim + History Compaction + Orphan Cleanup） |
| **跨任务** | KinetAios 长期记忆 | SQLite+FTS5 自动提取持久事实（如"华东区 Q3 平均停机率 3.2%"），下次分析自动注入 |

**任务交接增强**：KinetAios 的 `export_session` / `import_session` MCP 方法支持完整会话状态导出（turns + history + engine + cwd），Manager 可在 Worker 间迁移未完成任务，不丢上下文。

## 5. KinetAios MCP Server 实现细节

### 5.1 协议

标准 MCP JSON-RPC 2.0，HTTP POST + SSE response stream：

```
POST /mcp  (Accept: text/event-stream)
  Body: {"jsonrpc":"2.0","method":"tools/call","params":{"name":"run_agent","arguments":{"prompt":"..."}}}
  
Response: SSE stream
  data: {"jsonrpc":"2.0","result":{"type":"token","text":"..."}}
  data: {"jsonrpc":"2.0","result":{"type":"tool","name":"shell"}}
  data: {"jsonrpc":"2.0","result":{"type":"done","summary":"..."}}
```

### 5.2 暴露的 MCP 方法

| 方法 | 说明 |
|------|------|
| `tools/list` | 返回可用工具列表（按 Worker 角色过滤） |
| `tools/call` | 执行指定工具 |
| `run_agent` | 在远程机器上启动完整 AgentLoop（ReAct 循环 + 工具链） |
| `export_session` | 导出会话状态（任务交接） |
| `import_session` | 导入会话状态（接续执行） |

### 5.3 安全机制

| 机制 | 实现 |
|------|------|
| Token 鉴权 | 每个请求必须携带 Bearer Token |
| 沙箱降级 | 远程 Agent 强制 sandbox ≤ workspaceWrite，不可获得 fullAccess |
| 防递归 | 远程 Agent 的工具集排除 `dispatch_agent`（防止无限远程派发） |
| 超时保护 | 默认 5 分钟超时，防 Agent 无限运行 |
| SSRF 防护 | web_fetch 拦截内网 IP 和云元数据端点 |

### 5.4 代码位置

```
src/main/mcp-server.ts     # MCP Server 实现
src/main/tools.ts          # 12 个内置工具定义
src/main/AgentLoop.ts      # ReAct 循环
src/main/TaskManager.ts    # 会话管理 + Pipeline
```

## 6. 推荐技术映射

### 6.1 AgentTeams（必须）— 多 Agent 协同基座

| 能力 | 映射 |
|------|------|
| Manager-Worker 编排 | Manager 做任务拆解，KinetAios Worker 执行 |
| Matrix IM 协议 | Agent 间通信 + 人类全程可见可介入 |
| MinIO 文件共享 | Worker 间数据传递（CSV → 分析 → 报告） |
| 心跳监控 | Manager 定期检查 Worker 进度 |
| 零凭证架构 | Worker 只持 Higress 消费者令牌，KinetAios MCP Server 侧管 Token |

### 6.2 云 Skills（推荐）— Agent 操作云的能力

| 场景 | Skills |
|------|--------|
| 标准 OCR | 从 skills.aliyun.com 加载 OCR Skill |
| PDF 生成 | KinetAios office-suite 的 create_pdf 工具 |
| 数据分析 | KinetAios 自定义 Skills（停机率分析模板） |

**鉴权处理**：Skills 调用通过 Higress 网关统一鉴权，Worker 使用消费者令牌，不接触真实凭证。Nacos Skills Registry 管理已注册 Skills 的可见性和权限。

### 6.3 Nacos（推荐）— AI 管理中心

| 治理对象 | Nacos 能力 |
|----------|-----------|
| Worker 配置 | SOUL.md / AGENT.md 作为动态配置，热更新无需重启容器 |
| MCP 注册 | KinetAios MCP Server 实例注册为服务，Worker 通过 Nacos 发现 |
| Skills 注册 | office-suite 工具集注册为 Skills，按 Team 分配 |
| 模型路由 | Higress 从 Nacos 拉取最新模型路由策略 |

### 6.4 Higress（推荐）— AI 网关

| 策略 | 实现 |
|------|------|
| 统一模型路由 | Worker → Higress → Qwen/DeepSeek/GLM，支持 Fallback |
| Token 管控 | 每 Worker 独立额度，超限限流 |
| MCP Server 托管 | KinetAios MCP Server 注册到 Higress，Worker 通过网关访问 |
| 安全过滤 | 输入脱敏、输出安全过滤 |
| AI 缓存 | 语义缓存，相似分析请求命中缓存省 Token |

### 6.5 PolarDB-PG（推荐）— Agent 数据层

| 数据域 | 设计 |
|--------|------|
| 设备停机记录 | `downtime_records` 表，B-tree(device_id, dealer_id) |
| Agent 长期记忆 | `agent_memories` 表 + pgvector HNSW 索引 |
| 审计日志 | `audit_logs` 表，BRIN(ts) 时间索引 |
| 向量检索 | pgvector + cosine 距离，替代 KinetAios 本地 FTS5 |

**权限边界**：每个 Worker 使用独立数据库角色，行级安全策略（RLS）隔离数据。KinetAios 的 `recall_memory` 工具改为查询 PolarDB-PG 的 pgvector，而非本地 SQLite。

**可替换性**：数据层通过 MCP 协议抽象。替换 PolarDB-PG 为 MySQL/PostgreSQL/SQLite 只需更换 MCP Server 实现，不影响 Agent 逻辑。

### 6.6 UnifiedModel（推荐）— 统一数据建模

```
.unifiedmodel Device
  properties:
    device_id: string (PK)
    model: string
    install_date: date
  relations:
    → Dealer.installs
    → DowntimeRecord.device

.unifiedmodel Dealer
  properties:
    dealer_id: string (PK)
    region: string
    tier: enum
  relations:
    → Device.installed_by
    → DowntimeRecord.service_by

.unifiedmodel DowntimeRecord
  properties:
    record_id: string (PK)
    duration_hours: float
    reason: string
  relations:
    → Device.downtime
    → Dealer.services
```

Agent 通过 UnifiedModel 的 SPL 查询接口（`.umodel` / `.entity` / `.topo`）统一访问，无需关心底层是 PolarDB-PG 还是其他存储。

### 6.7 RocketMQ（推荐）— 事件驱动

| Topic | 生产者 | 消费者 | 用途 |
|-------|--------|--------|------|
| `task-request` | 用户/IM | Manager | 新任务入口 |
| `task-fragment` | Manager | Worker | 子任务分发 |
| `task-complete` | Worker | Manager | 完成通知 |
| `task-failed` | Worker | Manager + 人类 | 失败告警 |
| `agent-heartbeat` | Worker | Manager | 心跳上报 |

**可靠性设计**：
- 消息持久化，Worker 宕机后任务重投
- 同一任务内子任务按依赖串行消费
- 3 次失败进入 DLQ → Matrix 房间 @人类介入

### 6.8 AgentScope Studio / AgentLoop（推荐）— 可观测

| 观测项 | 数据来源 |
|--------|---------|
| 推理轨迹 | KinetAios AgentLoop 的每轮 ReAct 事件流 |
| Token 统计 | Higress 网关日志 |
| 工具调用 | KinetAios MCP Server 的 SSE 事件流 |
| 任务时延 | RocketMQ 消息时间戳差值 |
| 成本统计 | Higress Token 管控 API |

**数据飞轮**：AgentLoop Collect（收集轨迹）→ Analyze（分析瓶颈）→ Evaluate（评估质量）→ Optimize（优化 Prompt/工具配置）。

## 7. 安全边界

### 7.1 四层防护

```
┌─ 第 1 层：网络层（Higress）──────────────────────────┐
│ • 统一入口、WAF、限流                                │
│ • WAT 双身份：Agent 身份 + 操作者身份，全链路审计     │
│ • Token 管控：每 Worker 独立额度                     │
└─────────────────────────────────────────────────────┘
┌─ 第 2 层：Agent 层（KinetAios 沙箱）─────────────────┐
│ • 三级沙箱：readOnly / workspaceWrite / fullAccess   │
│ • 远程 Agent 强制降级为 workspaceWrite               │
│ • SSRF 防护：拦截内网 IP + 云元数据 + DNS rebinding  │
│ • 错误脱敏：返回模型的错误去掉绝对路径和用户名        │
└─────────────────────────────────────────────────────┘
┌─ 第 3 层：数据层（PolarDB-PG）──────────────────────┐
│ • 行级安全策略（RLS）隔离 Worker 数据                │
│ • 审计日志：每次 Agent 操作记录身份+时间+详情         │
│ • Agent 记忆隔离：每 Worker 独立记忆命名空间          │
└─────────────────────────────────────────────────────┘
┌─ 第 4 层：文件层（KinetAios 快照）──────────────────┐
│ • 每次 write/edit 前自动存入 .kinet-snapshots/       │
│ • 一键回滚到任意快照点                                │
│ • Agent 破坏不了文件系统                              │
└─────────────────────────────────────────────────────┘
```

### 7.2 异常分支处理

```
场景                          处理
─────────────────────────────────────────────────────────
工具执行超时                  KinetAios 5min 超时 → abort → 返回错误摘要
LLM 调用失败                  Higress 自动 Fallback 备用模型
上下文溢出                    KinetAios Reactive Trim 自动砍半重试
数据质量不达标                Manager 验收失败 → 打回重做（最多 3 轮）
Worker 容器宕机               RocketMQ 消息重投 → 其他 Worker 接管
KinetAios MCP Server 不可用   Higress 健康检查 → 标记降级 → Manager 切标准 Worker
```

## 9. 场景演示：Q3 设备停机率分析

### 9.1 输入
