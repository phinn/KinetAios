逐引擎深度分析
⚡V1 Direct
首选 · 9.2 分
  • Skill 直接拼入 systemPrompt，零损耗
  • 纯 ReAct 单循环，上下文 100% 用于数据
  • 三级 fallback（15K→7.5K→3.75K）+ compactHistory 摘要
  • 插件全可用：excel_read / csv_filter / excel_com / shell python
  • 只读工具同轮并发，多 Excel 同时读取
  • 无 checkpoint，崩溃需手动续
  • 无自动验证步骤（全靠模型自己判断）
📌 本场景最优解。Skill 注入 + 上下文利用率 + 工具链完整度三项第一。
🧠V2 Direct
不推荐 · 3.5 分
  • Plan JSON 本身消耗 2-5K token，数据还没读就已满
  • 每步 Verify 需要回顾数据 → 二次消耗
  • Judge 再调一次 LLM → 三次消耗
  • interStepCompact 在大数据场景下频繁触发 → 数据丢失
  • 有 checkpoint 断点续传（但此场景用不上）
  • 工具链共享 V1（理论可用，但上下文不够）
📌 设计目标是多步探索性代码任务，大数据场景严重水土不服。
🤖Claude Code
可用 · 7.0 分
  • Claude 自带上下文管理，长上下文处理优秀
  • --resume 恢复 session，可断点续
  • Bash + Read + Write 全链路可跑 python 脚本
  • --append-system-prompt 注入 Skill 内容（间接）
  • 无 KinetAios 插件工具（excel_read / csv_filter 全缺）
  • Skill 只能作为文字注入 prompt，不是一等公民
  • 每次对话 memory 是快照，不能 recall_memory 动态检索
  • 额外 CLI 进程开销 + stream-json 解析延迟
📌 能用但不够好。缺少插件生态意味着每步都走 Bash 绕路。
📦Codex
不推荐 · 5.5 分
  • 无 KinetAios 插件工具
  • 沙箱模式限制 shell 能力（read-only / workspace-write）
  • memory 前置拼到 prompt，最快照注入，无动态检索
  • JSONL 解析 + agent_message 去重逻辑开销
  • 无 --append-system-prompt 等效 flag
  • Codex 模型本身擅长代码 / 脚本
  • resume thread 可恢复
  • 沙箱安全性最高（但数据分析不需要）
📌 沙箱 + 无插件 + 无 Skill 注入，三重劣势。不如直接用 V1。
🎯
本场景的关键考量因素
📏
上下文窗口是瓶颈
多个 xlsx 解析后内容极长。每个额外的 Plan JSON / Verify 回顾都在抢占宝贵的上下文空间
🔌
插件工具是刚需
excel_read / csv_filter / csv_analyze / excel_com 是处理大数据的核心武器。Claude Code 和 Codex 没有这些
⚡
Token 效率即成本
V2 的 Plan+Verify+Judge 三次 LLM 调用让同样的分析任务 Token 消耗翻 2-3 倍，且多数验证对数据分析无价值
🧩
Skill 注入是一等公民
/ 指令在 V1 和 V2 中均直接进入 systemPrompt（isDirectFamily 守卫）。Claude Code / Codex 不走 skill 解析，只能降级为 prompt 文字
💾
记忆动态检索
V1/V2 支持 recall_memory 实时搜索历史（如"上次装机报告的格式"）。CLI 引擎只有快照注入，不能动态检索
🔄
三级 Fallback 保命
你已修好的 trimBudget 三级压缩(15K→7.5K→3.75K) + compactHistory。只有 V1 能在数据爆炸时优雅降级而不中断
⚡ 结论：多 Excel 交叉分析 → V1 Direct 引擎。Plan/Verify/Judge 的价值在代码任务，不在数据分析
