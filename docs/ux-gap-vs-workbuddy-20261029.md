# KinetAiosWin vs WorkBuddy — UX/用户体验差距报告

> 2026-10-29。样本:WorkBuddy V5.9.3(本机 macOS,asar 已拆,renderer 静态分析 + 实机截图)vs KinetAiosWin(current main)。
> 结论先行:**视觉档次 WorkBuddy 明显领先,交互功能面两边基本打平**;KinetAios 的"密度与信息量"更强,但输在打磨感、防呆与轻引导。

---

## 一、总览对比

| 维度 | WorkBuddy | KinetAiosWin | 差距判定 |
|---|---|---|---|
| 组件体系 | Radix Themes 全套(rt-Button/Select/DataList/Menu…)+ 设计 token | 手写 CSS,主题若干(aurora/serene…),无组件库 | **大** |
| 整体气质 | 亮色、留白、克制、Penguin 吉祥物人格化 | 高密度仪表盘,信息全,但拥挤、无喘息 | **大** |
| 工具调用呈现 | 单行摘要流 + 折叠详情 + 计时徽标 | 聚合卡(×N 步)+ step 明细 + 耗时 | 接近,KA 略强 |
| 产物卡片 | artifact-slot 双列 grid + 预览/版本管理 | 内联缩略图 + 文件抽屉(刚补齐) | 接近 |
| 计划确认 | submit_plan → 接受/拒绝大卡 | V3 DAG 规划卡(阶段分组+依赖) | KA 更强 |
| 定时任务 | 一级入口 + 引导式创建 | ⋯ → 📅 面板,功能齐 | WB 发现性更好 |
| 后台任务 | 聊天内 pill「1 个后台任务运行中」 | 状态栏 pill + jm 菜单 kill | 打平, WB 位置更贴流 |
| 引用/上下文 | @ 添加上下文、/ 技能与指令(输入框占位符直接教) | 文件 chip 可点,无 @ 补全面板 | **大** |
| 思维链 | 「深度思考」弱化单行,可展开 | 无独立 reasoning 渲染(Direct 协议不含) | **中**(协议层欠账) |
| 上下文管理 | 「上下文过长,建议开始新对话」主动劝导 | 无上下文用量指示 | **中** |
| 断点/重放/版本 | 文件版本时间线 + 重置 | checkResume/replay + 版本(29 处) | KA 更强 |
| 快捷键 | 标准编辑键 + 应用菜单 | 全局热键 + Enter 排队/⌘Enter 打断 | KA 更强 |

## 二、WorkBuddy 值得抄的 6 件事(按投入产出排序)

### 1. 输入框即教程(性价比最高,半天)
WB 占位符:`今天帮你做些什么? @ 添加上下文, / 调用技能与指令` —— 一句话把两个核心交互教了。
KA 现状:占位符是「Enter 排队 · ⌘Enter 打断」,只教了快捷键,没教 `/` 和引用。
**改法**:占位符轮换或合并为一句,把 `/ 命令`、`拖入文件`、`@引用` 亮出来。发现性差距由此一项抹平一半。

### 2. 「运行中」过程行内嵌消息流(1 天)
WB 把「⏱ 正在运行校验、查看文件: DebugPose.swift」作为**正文之间的灰字行**贯穿流式过程,读起来像叙事时间线;做完沉淀为可折叠节点。
KA 现状:工具过程集中在聚合卡里,和正文在视觉上是两个世界(卡 vs 文),过程感割裂。
**改法**:Direct 引擎流式期间,把当前执行的 tool 以轻量灰字行插在正文流内(完成后收敛进聚合卡),保持"读过程"的临场感。

### 3. 阶段横幅:过程段落化(1 天)
WB 用「继续处理任务过程 / 深度思考 / 已处理 30m52s」把长任务切成**章节**,长会话可扫读。
KA 现状:所有 step 平铺在一张聚合卡,50 步和 5 步长一样,回看时是墙。
**改法**:聚合卡内按 `status` 波次分段(每段 = 一轮 tool burst),段头给摘要(「探索 8 步 · 2m12s」)。

### 4. 上下文用量 + 主动劝新(1~2 天,依赖协议)
WB:「上下文过长,建议开始新对话」。
KA 现状:无任何上下文水位提示,撞上限才报错,体验是"突然失忆"。
**改法**:Direct 已知 prompt 组装过程,可在 cost/status 事件带 `contextTokens` → 顶栏 85% 时黄条 + 一键「归纳并开新对话」(复用现有 memory 提取,顺手)。

### 5. 组件级打磨(持续,无单点)
WB 的按钮/菜单/下拉全是 Radix:焦点环、键盘导航、hover 层次、动效曲线全是现成的对。KA 手写控件各有各的毛边(下拉无键盘导航、菜单无子层级延迟、hover 无过渡)。
**改法**:不引库(违背 local-first 轻量),但把 Radix 的**交互规范**抄过来:统一 `--dur/--ease` token、焦点环统一 2px、菜单支持 ↑↓/Esc、所有 hover ≤120ms 过渡。清一遍 styles.css 的毛边。

### 6. 人格化与情绪价值(1 天)
WB:吉祥物 + 「内容由 AI 生成,请核实重要信息」底部常驻免责 + 加载态有角色动画。
KA:纯工具脸。
**改法**:空状态/长任务等待时给轻量角色化反馈(哪怕是像素猫),成本低,记忆点高。

## 三、KinetAios 反超点(保持并放大,别被带偏)

1. **工程透明度**:cost/速率/耗时/步数全裸露,WorkBuddy 全藏。目标用户是开发者,这是身份认同,不要学它藏。
2. **断点续跑 + 会话重放**:47 处 checkResume/replay, WorkBuddy 没有同级能力。
3. **多引擎切换**(Direct/Claude Code/Codex)以及频道级模型/审批档位,WB 是单一 harness。
4. **跨会话长期记忆**:WB 只有会话内上下文,KA 的 recall_memory 是质变。
5. **Enter 排队 / ⌘Enter 打断注入**:比 WB 的 stop-only 细一个量级。
6. **文件抽屉 + Git/规则/团队 tab**:工作台属性比 WB 的"任务"概念更贴本地开发。

## 四、协议层欠账(想抄 #4/思维链必须先还)

- `AgentEvent` 无 `contextTokens`:上下文水位无法展示 → 加在 `cost` 或 `status` 事件,Direct 在组装 prompt 时已知粗估值。
- 无 reasoning 透传:glm.ts 未解析 `reasoning_content` → WB 的「深度思考」行就是它;Direct 若接深度思考模型,前端已能吃(applyEvent 加一类事件即可,改动单点)。

## 五、建议落地顺序(不动架构,全部 renderer 优先)

| # | 项 | 预估 | 依赖 |
|---|---|---|---|
| 1 | 输入框占位符即教程 | 0.5d | 无 |
| 2 | 过程行内嵌正文流(流式灰字行) | 1d | 无 |
| 3 | 聚合卡分段横幅(章节化) | 1d | 无 |
| 4 | 交互毛边清理(焦点环/键盘导航/hover token) | 1~2d | 无 |
| 5 | 上下文水位 + 劝新对话 | 2d | 协议加字段 |
| 6 | reasoning 思维链渲染 | 1d | glm.ts 解析 + applyEvent |
| 7 | 人格化空状态 | 1d | 无 |

> 总计 ~1.5 周纯 renderer/协议小改,不动引擎与存储。做完后「视觉档次」差距收窄到组件库级(可接受),交互面完成反超。
