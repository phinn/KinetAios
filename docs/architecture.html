10EngineContextPolicy — 引擎上下文策略体系

一个引擎的"上下文能力"不只是模型窗口大小,而是一组精心调校的预算参数: 何时裁剪历史、截断工具结果、压缩步骤间累积、给子 agent 透传多少上下文。 EngineContextPolicy 把这些魔数集中到一个策略对象,改一处生效全部引擎。

📋 EngineContextPolicy 类型 (shared/types.ts)

6 个字段,每个对应上下文管理的一个维度。不同引擎传入不同策略对象,运行时按需读取。

type EngineContextPolicy = {
  trimBudget:           number;  // reactive trim 预算(history 字符总和超则砍旧消息)。hifi 翻倍
  interStepCompactBudget: number;  // v2 步骤间 compact 预算(多步累积 history 摘要后塞回上限)
  truncateThreshold:      number;  // 单条 tool 输出最大字符数(头尾保留,中间省略)。hifi 翻倍
  appendStepSummary:      boolean; // v2 步骤完成时是否追加"步骤摘要消息"到 history
  stepSummaryMaxChars:    number;  // 摘要消息最大保留字数(超则截短,逼模型用 remember_fact)
  subAgentScope:          'none' | 'last_n_turns' | 'summary_only' | 'full_history';
};

⚙️ 四引擎策略对比 — ENGINE_POLICIES

每个引擎有独立的策略预设。核心差异:direct 轻量快响应、directV2 大预算重累积、CLI 引擎只给保底值(各自管 context)。

字段 direct

CLI		 codex

🔀 resolveEnginePolicy(engine, mode)

运行时合成函数:从 ENGINE_POLICIES 取引擎基础策略,再按 ContextMode 叠加调整。

standard 模式 → 直接返回 base policy
hifi 模式 → trimBudget ×2
interStepCompactBudget ×2
truncateThreshold ×2
// appendStepSummary 等不动

设计意图:hifi 让用户能"加预算"用于大文件分析 / 多数据源交叉,但不破坏 v2 的策略语义(stepSummary/subAgent 不翻倍)。

💡 为什么 hifi 不全局翻倍?

trimBudget ×2 — history 更长 → 保留更多上下文

truncateThreshold ×2 — 工具结果截断更宽松 → 不丢大文件内容

stepSummaryMaxChars 不变 — 摘要仍然精炼,逼模型用 remember_fact 存关键数据而非堆 history

subAgentScope 不变 — 子 agent 的上下文隔离策略不因主会话 hifi 而泄露

🔌 策略消费点 — 6 个字段在代码中如何生效

trimBudget → AgentLoop.ts:39

ReAct 循环每轮检查 history 总字符数。超 trimBudget 时,trimHistoryToTokenBudget() 砍旧消息。API 报"上下文过长"时,catch 分支用 trimBudget/2 激进裁剪后重试本轮。

interStepCompactBudget → DirectV2Engine.ts:928

v2 每步完成后,interStepCompact() 调 compactHistory() 把累积的 execHistory 摘要压缩到预算内,防止多步累积爆窗口。finalizeContext() 在整个任务完成时再做一次终态压缩。

truncateThreshold → AgentLoop.ts:557,567

工具执行后,truncateForModel(result, threshold) 按 37.5%头 + 37.5%尾 + 25%省略号 比例截断。模型拿截断版(省 input token),UI 拿完整原文(可点击展开)。

appendStepSummary + stepSummaryMaxChars → DirectV2Engine.ts:218,355

v2 每步完成,从 step.result 提取 stepSummaryMaxChars 字符的摘要,追加为 user 消息。后续步骤即使被 trim/compact,也能从摘要得知前步结论。超 500 字 → 截短 + 提示"用 remember_fact 存大数据"。

subAgentScope → engines.ts:302-313

dispatch_agent 默认 scope。不走 ChatMsg[] 直接传(避免 tool_call role 错位),而是 resolveSpawnHistory() 把 parent history 转成文本拼到子 agent 的 userInput 末尾。模式:none=独立 / last_n_turns=最近3轮 / summary_only=摘要 / full_history=全量(>8000 字符 auto-compact)。

📈 standard vs hifi 模式实际效果 (以 DirectV2 为例)

📦 standard 模式
trimBudget: 30,000
interStepCompact: 20,000
truncateThreshold: 6,000
stepSummaryMax: 500 (不变)
subAgentScope: last_n_turns (不变)

适合:日常编程、bug 修复、快速问答

🔥 hifi 模式
trimBudget: 60,000 ×2
interStepCompact: 40,000 ×2
truncateThreshold: 12,000 ×2
stepSummaryMax: 500 (不变)
subAgentScope: last_n_turns (不变)

适合:大文件分析、多数据源交叉、复杂架构审查

🎯

单一真相源

所有"上下文魔数"集中在 ENGINE_POLICIES 一个 Record。加引擎 = 加一个 key,不改 AgentLoop 任何分支判断。

🔒

策略不可叠加

hifi 只翻倍数值字段,不改 boolean/scope。防止"高保真"意外打开 appendStepSummary 或泄露子 agent 隔离边界。

⚡

调用方透传

RunOpts.policy 可选 — 不传则 resolveEnginePolicy() 自动解析。子 agent / team member 不传 policy,默认走 direct 标准策略。

11三层记忆架构 — Memory Blocks · Importance · Episodic · Reflection

KinetAios 的记忆系统借鉴 MemGPT/Letta 的分层设计,将 Agent 记忆分为三层:核心记忆(常驻上下文)、长期记忆(向量检索)和情景记忆(会话摘要)。 每轮对话异步提取事实 → 加权打分 → 注入下一轮。后台自动执行 Reflection GC,防止噪声堆积。

🧠 三层记忆模型 (Inspired by MemGPT / CoALA)

● project_context
● active_goals

Long-term Memory

● scoredMemories() 重排
● importance × 0.5 + recency × 0.3
● 每轮提取 → LLM 打分 1-10

recallForInjection() → top-15 注入
L3 · 会话级
Episodic Memory

每次会话结束自动生成叙事摘要 + 标签,跨会话回忆"上次做了什么"。

💡 done 事件 → 异步生成摘要
episodic_memories 表持久化

📊 P1 · Importance Scoring — 加权检索策略

传统 FTS5 只按相关性排序,无法区分"用户核心偏好"与"一次性细节"。KinetAios 在提取阶段让 LLM 对每条记忆打分(1-10), 检索阶段用三因子加权重排。

📹 P2 · Episodic Memory — 会话级叙事摘要

每次 done 事件异步触发 extractEpisodicMemory(),LLM 将整轮对话浓缩为 3-5 句叙事摘要 + 标签 + 重要性评分。 最近 5 条摘要注入到 memoryBlock() 顶部,让 Agent 在新会话中立即看到"最近做了什么"。

📝 提取流程
done 事件
→ 收集本轮所有 turns
→ LLM 生成叙事摘要 (3-5 句)
→ 输出: { summary, tags[], importance }
→ INSERT INTO episodic_memories
→ 保留最近 20 条 (超限自动清理)

🧹 P3 · Idle Reflection — 后台记忆 GC

记忆会随时间堆积噪声。runIdleReflection() 在每 5 次 done 事件后自动触发,执行三步 GC:

🔀
① dedupMemories()

LLM 识别语义重复的记忆,合并为一条。保留最高 importance。

📉
② decayMemories()

长期未引用的记忆 weight ×0.7。低于 0.1 的直接清除。

🗑️
③ pruneLowImportance()

importance ≤2 且从未被 recall 命中的噪声记忆 → DELETE。

// 触发条件
TaskManager.doneCounter % 5 === 0 → runIdleReflection() (异步,不阻塞用户输入)
// 手动触发
IPC: memory-reflection handler → 返回 { deduped, decayed, lowImportancePruned }
🏗️

三层分离

Core (常驻) / Long-term (检索) / Episodic (摘要) 各司其职。不混淆注入策略和衰减规则。

⚖️

异步提取

extractMemories / extractEpisodicMemory 均为 fire-and-forget,不阻塞 done 事件返回。用户无感知。

🔄

Agent 可自编辑

memory_replace / memory_append 让 Agent 像编辑笔记一样更新自己的认知。非强制 read-only。
