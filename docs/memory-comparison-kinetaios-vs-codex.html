7优缺点对比

🔵 KinetAios

✅ 优势
  • 语义检索精度高:Embedding cosine + FTS5 + scoredMemories 三级混合,召回率远超 grep

  • 三维加权评分:importance×0.5 + recency×0.3 + relevance×0.2,科学排序
  • 知识图谱:主谓宾三元组支持语义推理(Memory Graph)

  • Session Anchors:conv_facts 跨步骤共享中间产出
  • 五层记忆架构:Blocks / Facts / Episodic / History / Anchors 分层明确
❌ 不足
  • 不可读性:SQLite 二进制存储,用户无法直接查看/编辑记忆
  • 无 LLM 合并:去重靠 cosine > 0.85 硬阈值,不语义合并
  • 无 Skills 沉淀:不提取可复用工作流/检查清单

  • Embedding 成本:每次提取需调用 embedding API

9结论与互补建议

设计哲学差异

KinetAios 走的是 数据库 + 向量检索 路线: 记忆是带索引、带评分、带衰减的结构化数据。优势在于检索精度和实时性, 每轮对话即时提取、embedding 语义召回、三维加权排序。适合需要高 recall/high precision 的场景。

Codex 走的是 文件系统 + LLM 子代理 路线: 记忆是 Markdown 文件,Progressive Disclosure 引导 LLM 按需检索。 优势在于人类可读性、Skills 沉淀、LLM 语义合并。 用户可以直接 cat ~/.codex/memories/MEMORY.md 查看和编辑记忆,也可以 Git 版本控制。

KinetAios 可以从 Codex 借鉴的

  • Skills 沉淀:从记忆中提取可复用工作流(SKILL.md 模式),而不仅仅是原子事实
  • LLM 合并:用 LLM 做语义级 deduplicate,而非 cosine > 0.85 硬阈值
  • 人类可读导出:提供一个 /memories export 命令导出 Markdown 视图
  • LLM Compaction:上下文压缩用 LLM 生成结构化 handoff summary,而非字符截断
  • 措辞保留:提取 prompt 增加"保留原始 error string / API name / 文件名"指令

Codex 可以从 KinetAios 借鉴的

  • Embedding 检索:给 MEMORY.md 建向量索引,cosine 召回替代 grep
  • 实时提取:对话中增量提取,而非启动时离线批量
  • 三维评分:importance + recency + relevance 加权排序
  • 数值化衰减:跟踪 use_count + last_used,指数衰减淘汰
  • 知识图谱:维护三元组,支持语义推理

⚡ 结论: KinetAios 在检索精度、实时性、跨引擎、评分排序、知识图谱上明显领先; Codex 在人类可读性、Skills 系统、LLM 合并、上下文压缩上更有优势。 两者代表了 AI Agent 记忆系统的两种范式 — 数据库派 vs 文件派, 各有适用场景。KinetAios 更适合多引擎聚合的 AI 仪表盘定位,Codex 更适合单引擎深度 Coding 场景。
